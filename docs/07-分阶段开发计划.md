# 07 — 分阶段开发计划

| 项目 | 内容 |
| --- | --- |
| 文档版本 | v0.1（设计阶段草案，待确认后启动 Phase 0） |
| 前提 | 本计划假定 1 名前端 + 1 名后端/算法可并行；单人执行时按「前端串行、后端延后」节奏，工作量按人日估 |

## 0. 总览与里程碑

| 阶段 | 名称 | 核心产出 | 前端 | 后端 | 里程碑演示物 |
| --- | --- | --- | --- | --- | --- |
| P0 | 脚手架与设计系统 | 可运行的壳 + token + Mock 基建 | 4d | — | 全站空壳可导航，设计 token 落地 |
| P1 | Dashboard + Workspace | 两核心页（Mock 数据） | 6d | — | **演示：Mock 剧本跑通含审批暂停的完整任务** |
| P2 | 资产与观测四页 | Skill/Context/Workflow/Evaluation/Settings | 7d | — | 七页全部可演示（Mock） |
| P3 | 前端验收与打磨 | 三态/响应式/可访问性收口 | 3d | — | 前端 Mock 版验收（UI 评审 checklist） |
| P4 | 后端骨架 | FastAPI + DB + REST 联调 | 2d | 7d | 前端切 `live` 模式读真实数据 |
| P5 | Agent 核心闭环 | LangGraph 多智能体 + MCP + SSE 真流 | 4d | 12d | **演示：真实任务端到端（规划→工具→测试→审批）** |
| P6 | 进化与评测闭环 | Skill 自进化 + 评测体系 | 4d | 10d | **演示：失败任务 → 候选 Skill → 审核 → 生效** |

> P0~P3 前端先行（全程 Mock，无后端依赖）；P4~P6 后端逐步接管，前端只做联调与小改。两段之间无阻塞，可压缩总周期约 20%。

## 1. Phase 0 — 脚手架与设计系统落地（前端 4d）

**范围**
1. Vite + React + TS(strict) + Tailwind + shadcn/ui 初始化；ESLint/Prettier/`tsc --noEmit` 质量门。
2. 按 doc 03 落地全部 CSS 变量与 Tailwind 映射（`styles/globals.css`）。
3. `app/` 外壳：AppShell、Sidebar（含折叠/移动端 TabBar）、TopBar、路由表（doc 02 全路由 + lazy）、路由级 ErrorBoundary、页面切换动画。
4. `components/common` 基础件：StatusDot/StatusBadge/MockBadge/EmptyState/ErrorState/PageSkeleton/ConfirmDialog/TimeAgo。
5. `api/client.ts`（fetch 封装）+ MSW 接入（`VITE_API_MODE` 开关）+ `types/api.ts` 全量契约类型。
6. 按 doc 04 建立全部 feature 目录骨架（每页一个占位 Page + PageSkeleton）。

**验收标准**
- [ ] 七个路由全部可导航，标题/图标与 doc 02 一致；404 页生效。
- [ ] 设计 token 全部生效：抽查卡片/按钮/Badge 无硬编码色值（ESLint 规则约束）。
- [ ] 移动端 <1024px 底部 TabBar 正常；Sidebar 折叠态保持。
- [ ] `npm run build` 通过且首屏分包正常（路由级 chunk）。

## 2. Phase 1 — Dashboard + Agent Workspace（前端 6d）

**范围**
1. `api/sse.ts` + `useRunStream`（重连/Last-Event-ID/心跳超时）。
2. `mocks/eventPlayer.ts` 剧本引擎：完整任务剧本（计划→工具→diff→测试）+ 审批剧本（暂停→等 POST /approvals→继续）。
3. Dashboard 全部区块（doc 05 §1），图表组件封装（ChartCard/TrendArea/StackedBar/Donut）。
4. Workspace 三栏全部组件（doc 05 §2）：ConversationPanel、EventStream + 四类内联卡、PlanTree、ApprovalCard、ContextGauge 迷你版。
5. 创建任务 → Mock 流式执行 → 审批交互 → 完成的完整闭环体验。

**验收标准**
- [ ] Dashboard 四块 Mock 区块全部带 `MockBadge`；KPI/图表三态（loading/empty/error）可用。
- [ ] Workspace 剧本可完整播放：事件实时插入、时间线自动滚动、新事件提示、筛选 chips 生效。
- [ ] 审批卡批准/拒绝后剧本行为不同（拒绝 → Replanner 重规划分支）；SSE 模拟断线可自动恢复并补拉缺口。
- [ ] 响应式：Workspace 移动端三段切换可用。

## 3. Phase 2 — Skill / Context / Workflow / Evaluation / Settings（前端 7d）

**范围**
1. Skill Center：主从布局、版本时间线、diff Dialog、候选审核抽屉（含批准/拒绝 + 回归评测对比）。
2. Context Center：ContextGauge 大仪表、Token 分布堆叠面积、压缩时间线、记忆四层、检索测试器。
3. Workflow Center：React Flow 封装（AgentNode/ConditionalEdge）、Run 列表、回放控制、NodeDetailSheet、移动端 BottomSheet。
4. Evaluation Center：五类图表 + 明细表（KPI 复用 MetricCard）。
5. Settings 五面板（含工具权限矩阵、MCP Server 卡片、连通性测试 Mock）。

**验收标准**
- [ ] 五页全部对齐 doc 05 线框；tab/筛选/选中态写 URL 可深链。
- [ ] Workflow 回放：节点状态随回放点亮，failed 分支边标签正确；画布缩放/小地图可用。
- [ ] Skill 审核：批准后列表版本号 +1 且新版本入时间线（Mock 状态自洽）。
- [ ] Settings 表单 dirty 提示、乐观更新 + 可撤销 Toast 生效。

## 4. Phase 3 — 前端验收与打磨（前端 3d）

**范围**：全站三态补齐、键盘可达与焦点管理、`prefers-reduced-motion`、性能（虚拟滚动抽查、图表按需渲染）、UI 评审 checklist 过一遍（MockBadge/状态色/间距栅格/文案语气）。

**验收标准**
- [ ] doc 03 §8 可访问性基线全部通过；Lighthouse a11y ≥ 90。
- [ ] 全站无「裸空态」；所有 Mock 区块标注完整。
- [ ] 断点抽查：375 / 768 / 1024 / 1440 / 1920 五档无布局破碎。

## 5. Phase 4 — 后端骨架与 REST 联调（后端 7d，前端 2d）

**范围**
1. FastAPI 工程（doc 06 §6 结构）、docker-compose（PG/Redis/Chroma）、alembic 迁移。
2. Pydantic schema 与 `types/api.ts` 全量对齐（以 §3 接口为准，先 CRUD 与查询类）。
3. Tasks/Runs/Skills/Settings 等只读与写入接口落地（数据来自脚本注入的种子数据，非 Agent 产出——**明确不虚构 Agent 能力**）。
4. 前端切 `live` 模式联调；MSW 保留为开发/演示工具。

**验收标准**
- [ ] `docker compose up` 一键起环境；`/api/v1/*` OpenAPI 文档可访问。
- [ ] 前端 `VITE_API_MODE=live` 下 Dashboard/Skills/Settings 显示真实库数据（种子数据）。
- [ ] 错误体/分页/时间格式与 §1 约定一致；前端错误提示统一。

## 6. Phase 5 — Agent 核心闭环（后端 12d，前端 4d）

**范围**
1. LangGraph 编排：Planner/Executor/Reviewer/Replanner 状态机 + 重试/重规划边（对齐 Workflow Center 图）。
2. GLM 接入（`glm-5.3` / `glm-5.3-flash`）+ Model Router 策略引擎（读 Settings 路由规则）。
3. MCP 客户端：filesystem / git / search / tests 四个 Server 接入；工具注册表与风险级别标注。
4. Harness：权限矩阵执行、命令沙箱（容器内执行测试等）、失败重试、审批闸门（Redis 挂起 → API 恢复）。
5. 事件总线：LangGraph 节点 → Redis Stream → SSE endpoint（§4 全事件）+ `run_events` 落库补拉。
6. Context 基础版：窗口组装 + 阈值触发压缩 + `context.updated` 事件；记忆写入（episodic/semantic 两层先行）。
7. 前端：Workspace 真流联调、断线续传实测、Context Center 接真数据。

**验收标准**
- [ ] 真实任务端到端：输入需求 → 真计划 → MCP 工具执行 → 代码修改 → 容器内测试 → 完成/失败落库；全程 SSE 实时可见。
- [ ] 危险工具触发真实审批暂停，批准后继续（与 Mock 演示行为一致）。
- [ ] 模型路由按规则分流（日志可验证）；SSE 断网 30s 恢复后事件不丢。
- [ ] 上下文超阈值自动压缩并在 Context Center 可见压缩事件。

## 7. Phase 6 — Skill 进化与评测闭环（后端 10d，前端 4d）

**范围**
1. 反馈信号采集：任务成败、审查意见、重试次数 → 经验提取器生成候选 Skill（新增/修订）。
2. Skill 版本库（git-backed）+ 回归评测器（进化前后跑同一评测集）+ 候选审核流。
3. Evaluation 数据闭环：eval overview / models / skills / compression 接口真实化；评测批次表。
4. 记忆补全：procedural/core 层 + 记忆检索测试器接 Chroma 真数据。
5. 前端：Skill Center 全功能接真、Evaluation 全图表接真、Dashboard 汇总接真；移除最后一批 MockBadge。

**验收标准**
- [ ] 演示闭环：构造一个失败任务 → 系统提出候选 Skill（附证据任务与评测对比）→ 批准 → 新版本生效 → 下一个同类任务引用该 Skill 且成功率提升可见。
- [ ] Skill 回滚可用且生成回滚事件；候选拒绝有记录。
- [ ] Evaluation 四类数据全部来自真实执行记录，页面可解释（图表注明统计口径）。

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| GLM API 限流/不稳定 | 路由引擎内置降级（Flash 兜底）+ 重试退避；评测任务错峰执行 |
| 沙箱执行环境差异（Windows 开发机） | 沙箱统一跑在容器内；本地开发提供 `mock-exec` 模式 |
| SSE 在代理/浏览器下的兼容问题 | 心跳保活 + `Last-Event-ID` 续传 + 事件落库补拉三重保障 |
| Skill 进化质量失控 | 候选必须过回归评测集 + 人工审核双重门槛；保留回滚 |
| Mock 与真实行为偏差 | 类型同构 + 事件 schema 单一来源（doc 06），联调期以真实事件回放替换剧本 |
| 范围蔓延 | P0~P6 范围即合同；新需求进 backlog，P2 后统一评估 |
