## 一、一页结论

项目处于 **「双端骨架完成、真实数据链路未打通」** 阶段：

- **后端**：Phase 1（基础工程）完成态，质量高。core / db / models（20 表）/ 统一异常体系 / 3 条健康探针全部真实现，17 个测试通过；但 **17 张业务表无一有对应 API**，LangGraph、SSE、MCP、Chroma、Skill 进化全部缺位（依赖均未安装，属计划内缺位而非烂尾，全库 0 个 TODO/FIXME）。
- **前端**：工程骨架（路由 / 布局 / 设计系统 / API 客户端 / 347 行全量类型契约 / 337 行 MSW 剧本引擎）完整且质量好，`npm run build` 通过；但 **8 页中 5 页纯占位**，且 `.env.development` 与 `.env.production` 均为 `VITE_API_MODE=mock` —— **当前不存在任何接真后端的路径，生产构建也是纯假数据**。
- **契约**：前端定义 52 个接口常量，与后端实际匹配 **0 个**；15 个前端已接线的接口后端全部缺失；1 个路径不匹配（`/system/health` vs `/api/v1/health`）。
- **文档**：docs/07 全部 25 项验收复选框未勾选、README 声明「尚未编写任何功能代码」，与仓库实况（迁移已应用、测试全过）矛盾 —— **文档进度声明落后于实现**；另有 7 处文档间矛盾待裁决（见 §四）。
- **规划缺口**：八大能力中「企业文档解析」「多模态理解」在 9 份文档中**零设计**，需要用户裁决是补设计还是从本期范围移除。

**下一阶段建议（M1）**：实现后端第一批业务 API（tasks / runs / dashboard 域）+ 前端切 live 接真，打通「创建任务 → 列表/详情 → 审批」的第一条真实数据链路。依据开发原则 1「优先保证真实功能，不做只有界面没有后端逻辑的展示型功能」，优先打通真实链路，再扩展占位页面。

## 四、发现的问题与风险（按优先级）

### A. 需要用户裁决 / 文档裁决

1. **[裁决] 能力 7、8 无设计**：企业文档解析、多模态理解在 9 份文档中零覆盖，而 docs/07 §8 称「P0~P6 范围即合同」。需决定：纳入并补设计文档，还是明确移出本期范围。
2. **[裁决] 阶段编号双轨制**：doc07 P0~P6 与 doc08 P1/P2/P3 无对照表，同一「P1」两义。建议在 docs/07 加一张对照表，后续沟通统一用 doc07 编号（本报告的里程碑用 M 编号避让）。
3. **[文档修订] 7 处文档矛盾**：①README/PRD「未开始编码」与实况不符；②健康检查路径两版（`/system/health` vs `/api/v1/health`）；③Context Snapshot 两版模型（PRD 1:1+独立事件表 vs doc08 v0.2 决策 1:N 版本化，代码已按后者落库）；④Message 归属两版；⑤doc06 后端草图含 harness/router/events 包且写 SQLModel，doc08 定稿无；⑥doc08 §3.3 与 §7 决策 3 自相矛盾（conversations.task_id UNIQUE vs 普通索引，代码已按普通索引落库）；⑦若干引用瑕疵（doc04 误指 doc06 §8、doc01 漏列 doc08 等）。

### B. 接真链路阻塞项（M1 必须处理）

4. **[高] 前端切 live 三缺一**：`.env.production=mock`、vite 无 dev proxy、`VITE_API_MODE` 未设置时 UI 显示 mock 但 MSW 未启动（connectionStore 默认值与 main.tsx 判断条件不一致）。
5. **[高] 后端业务 API 全缺位**：15 个前端已接线接口无路由；Idempotency-Key 前端已自动携带、后端无处理。
6. **[中] 健康指示假绿灯**：`setApiHealthy` 零调用、无轮询；Dashboard KPI delta 硬编码字符串（"+8.2%"）与真算数据混排。

### C. 代码瑕疵（小，可随 M1 顺手修）

7. `services/health.py:29` api_latency 恒 ≈0，字段无度量意义。
8. `ENV=prod` 时 /docs、/openapi.json 未关闭；`db_session()` 请求结束自动 commit 的语义未定义。
9. mock `GET /tasks` 忽略分页/筛选参数，分页逻辑从未被演练；Dashboard 无刷新机制。
