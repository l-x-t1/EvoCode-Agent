### 区域与组件

| 区域 | 组件 | 关键 props / 交互 |
| --- | --- | --- |
| KPI 行 | `MetricCard` ×4 | `{label, value, delta?, sparkline?, to?}`；运行中卡的数值旁挂 `StatusDot(running)` 脉冲；点击跳转对应页面 |
| 图表行 | `ChartCard` > `TrendArea` | `{series: created/succeeded/failed, range}`；范围切换写 `?range=`；hover 显示 tooltip（日期、任务数、成功率） |
| 图表行 | `ChartCard` > `StackedBar` | `{series: glm-5.3, glm-5.3-flash}`；图例可点选隐藏系列 |
| 内容行 | `RecentTasksTable` | 列：任务标题 / `StatusBadge` / 模型 tag / 耗时 / Token；行点击 → `/workspace/:taskId`；最多 8 行 + 「查看全部」 |

### 状态设计

- Loading：KPI 用 `Skeleton`，图表用 `ChartCard` 内置空态动画（进度弧）。
- Empty（全新安装）：KPI 显示 0 值 + 引导卡「创建第一个任务」。
- Mock 标注：图表行、Agent 环形、进化动态、系统健康四块挂 `MockBadge`。

**移动端**：KPI 2×2 网格；图表纵向堆叠；最近任务改卡片；Feed/健康面板收纳进「更多」Tab。

### 区域与组件

| 区域 | 组件 | 关键 props / 交互 |
| --- | --- | --- |
| 头部 | `TaskHeader` | `{task}`：`StatusBadge` + 标题 + 模型 tag + 所用 Skill chips（点击跳 Skill Center）+ 耗时计时；右侧动作：查看执行图（→`/workflow/:runId`）、取消任务（`ConfirmDialog`）、任务列表抽屉 |
| 左栏 | `ConversationPanel` | 消息按角色 `AgentAvatar` + 角色色左边框；`AgentMessage` 内的 Markdown 渲染；滚动跟随 |
| 左栏 | `TaskInput` | 多行 Textarea + 附件按钮（规划项，禁用态带 tooltip）+ 模型选择器（继承路由策略时显示「自动」）；Enter 发送 / Shift+Enter 换行；提交 → `POST /tasks` → 跳转新任务 |
| 中栏 | 事件筛选 chips | `全部/工具调用/代码/测试/审批`，前端过滤 `EventStream`，选中项写 `?filter=` |
| 中栏 | `EventStream` > 内联卡 | 时间正序；新事件淡入（180ms）；自动滚动至底部，用户上滚时出现「回到底部 N 条新事件」悬浮按钮 |
| 中栏 | `ToolCallCard` | `{call}`：头部 = 状态点 + 工具名(mono) + server tag + 风险 Badge(safe/危险琥珀) + 耗时；展开 = 参数代码块 + 结果摘要；失败卡红色描边 |
| 中栏 | `DiffViewer` | `{diffs}`：文件行（+N −M 统计）→ 折叠展开 unified diff；等宽字体，+行绿 soft / −行红 soft；超过 400 行默认折叠显示「展开剩余 N 行」 |
| 中栏 | `TestResultCard` | `{result}`：通过/失败/跳过统计 + 迷你环形 + 失败用例 mono 列表（可复制） |
| 中栏 | `ApprovalCard` | `{approval}`：琥珀描边置顶吸附（非阻塞滚动）；工具名 + 参数摘要 + 影响说明；按钮 [批准](primary) [拒绝](danger-soft)；点击 → `POST /approvals/:id`，卡片转为已处理态（含结果时间） |
| 右栏 | `PlanPanel` > `PlanTree` | `{plan}`：步骤状态图标(○待办 ▶进行中脉冲 ✓✗) + Agent 徽标；「重规划」步骤显示 fork 图标与原步骤划线；点击步骤滚动时间线到对应事件 |
| 右栏 | `ContextGauge`（迷你） | 62% 用量环形 + 6 段色条；点击 → `/context/:sessionId`；Mock |
| 右栏 | `ArtifactsPanel` | 变更文件列表（+N −M）点击展开 diff 定位；测试报告入口；Mock |
| 右栏 | 待处理审批汇总 | 有 `waiting_approval` 时右栏顶部出现琥珀提示条（移动端为全局顶栏提示） |

### 状态设计

- `/workspace` 无任务：`EmptyState`（大输入框直接成为新建入口）+ 最近任务 3 张卡。
- 任务加载中：三栏各自 `PageSkeleton`。
- SSE 断连：中栏顶部黄色细条「实时连接中断，正在重连…」，恢复后自动补拉缺口事件（`Last-Event-ID`）。
- Mock：`eventPlayer.ts` 剧本驱动（含审批暂停 → 演示者点批准 → 继续执行直到完成）。

**移动端**：单列 + 底部三段切换（会话 / 时间线 / 计划）；`ApprovalCard` 出现时全局吸顶提醒；`TaskHeader` 可折叠为一行。

### 区域与组件

| 区域 | 组件 | 关键 props / 交互 |
| --- | --- | --- |
| 顶部 | 搜索/筛选 | `?q= &category= &status=` 写入 URL；候选徽标点击展开审核队列 |
| 左栏 | `SkillCard` | `{skill}`：名称 + 版本 + `StatusBadge` + 成功率迷你条 + 使用次数；选中态紫色 soft 底 |
| 右栏 | `SkillDetailPanel` > Tabs（tab 写 URL） | 见下 |
| 概览 | 描述/参数表/指标卡 | 指标：使用次数、关联任务成功率、平均 Token 增益、进化次数 |
| 版本 | `VersionTimeline` | 垂直时间轴；每版本：版本号、变更摘要、来源 Badge（任务 #id / 人工 / 进化）、[查看 diff]（Dialog 双栏对比）、[回滚到此版本]（`ConfirmDialog` → `POST rollback`） |
| 进化 | `EvolutionHistory` | 事件流：时间 + 触发原因（失败重试/审查意见/模式识别）+ 来源任务链接 + 变化统计（±行） |
| 评测 | `SkillBeforeAfterChart`（复用 Evaluation 组件） | 配对柱状：进化前/后 成功率与 Token |
| 审核队列 | `CandidateReviewPanel`（Drawer，lg 内嵌右列） | 候选列表（新增/修订 vN+1）；详情 = 建议内容 diff + 证据任务列表（可跳 Workspace）+ 回归评测对比（Mock）+ [批准合入] [拒绝]（均需 `ConfirmDialog`） |

### 状态设计

- 列表空态：引导「完成任务后，Agent 会自动提议第一个 Skill」（说明进化尚未发生，非报错）。
- 审核队列为空：插画级 `EmptyState`「暂无待审候选」。
- Mock：Skill 库 6~8 个、候选 2~3 个（含一个「修订」一个「新增」案例）。

**移动端**：主从变两段式（列表页 → 详情页）；审核入口为浮动徽标按钮。

## 8. 跨页面通用规范

1. **三态齐备**：每个数据区块必须实现 loading（Skeleton）、empty（引导动作）、error（重试按钮）三态，缺一不入库。
2. **MockBadge 规则**：Mock 驱动的卡片/图表右上角统一挂角标；页面级 Mock 在 PageHeader 右侧挂一次即可，避免重复。
3. **深链一致性**：文档中所有「点击 →」跳转路径与 doc 02 路由表一致，开发时以两端为准交叉校对。
4. **空态文案语气**：说明「为什么是空的」+「下一步做什么」，禁止只写「无数据」。
