## 1. 前后端契约核对结论（先行确认）

| 契约点 | 前端现状 | 后端必须遵守 |
| --- | --- | --- |
| 成功响应 | **裸实体 JSON**（无 `{code,data}` 包装），`client.ts` 直接 `res.json()` | 成功 → 直接返回实体；**不要**再套响应信封 |
| 错误响应 | `{"error": {"code","message","details?"}}` + HTTP 语义状态码 | 统一异常处理器输出该结构 |
| 分页 | `{items, total, page, size}` | 列表接口一律此结构；事件类用游标 `?after=seq` |
| 时间 | ISO 8601 UTC 字符串 | `timestamptz` + Pydantic 序列化为 UTC ISO |
| ID | 带前缀字符串（`task_01J…` / `run_…` / `skill_…`） | DB 主键用「前缀 + ULID」字符串，前后端免转换 |
| SSE | 帧格式 `event/id/data`，信封 `{v,seq,ts,runId,payload}`，`Last-Event-ID` 续传，15s 心跳 | 事件表按 `(run_id, seq)` 唯一，支持断点续拉 |
| 枚举 | 8 个 TaskStatus、6 个 AgentRole、3 个 RiskLevel 等 | DB enum / Pydantic Literal 与前端**逐字一致** |

> ⚠️ 需要你确认的决策：**不做 `{code,message,data}` 全局包装**。理由：前端已按裸实体 + 错误信封实现（P0~P1 全部页面），改包装会破坏兼容性（违反开发约束「保留前后端接口兼容性」）。

## 3. 数据库 ER 设计

### 3.1 实体总览与「需求实体 ↔ 前端契约」映射

你指定的 10 个核心实体全部保留；**带 ➕ 的是前端契约所必需的补充实体**（否则 Task/Run、工具卡、审批、评测页无表可依）：

| 你的需求 | 数据库表 | 对应前端类型 | 说明 |
| --- | --- | --- | --- |
| User | `users` | —（P1 无鉴权） | 预留，seed 单个本地用户 |
| Conversation | `conversations` | Task 内嵌消息流 | **与 AgentTask 1:1**（一个任务即一个会话线程） |
| Message | `messages` | `Message` | `run_id` 可空（用户首条消息先于 Run 产生） |
| AgentTask | `agent_tasks` | `Task` | 聚合 stats 冗余列，供 Dashboard 汇总 |
| AgentExecutionLog | `agent_execution_logs` | SSE 事件帧 | 事件溯源表：`(run_id, seq)` 唯一，支撑续传 |
| Skill | `skills` | `Skill` | |
| SkillVersion | `skill_versions` | `SkillVersion` | git-backed 内容存储在 P3 引入，本期 DB 存正文 |
| SkillEvaluation | `skill_evaluations` | `SkillCandidate.evaluation` 源数据 | 进化前后对比的落库层 |
| ContextSnapshot | `context_snapshots` | `ContextSession` | **与 Run 1:N 版本化**（v0.2 修订：每次压缩生成新快照，保留历史，`is_current` 标识当前有效版本） |
| ModelUsage | `model_usage` | Dashboard/Evaluation 聚合源 | 每次模型调用一行 |
| ➕ | `agent_runs` | `Run` | Task 1─n Run（重跑产生新 Run） |
| ➕ | `plans` / `plan_steps` | `Plan` / `PlanStep` | 计划带 revision，重规划追加新 plans |
| ➕ | `tool_calls` | `ToolCall` | 工具卡结构化投影 |
| ➕ | `approvals` | `Approval` | Harness 审批记录 |
| ➕ | `skill_candidates` | `SkillCandidate` | 候选审核队列 |
| ➕ | `memory_items` | `MemoryItem` | PG 存元数据；向量在 Chroma（P3） |
| ➕ | `eval_runs` / `eval_cases` | `EvalRun` 及明细 | 评测批次 |
| ➕ | `settings` | `ModelSettings` 等 5 域 | KV + JSONB，与前端 GET/PUT 对齐 |

### 3.2 ER 图

```
users ──1:n── agent_tasks ──1:n── agent_runs ──1:n── agent_execution_logs (seq 递增, UNIQUE(run_id,seq))
  │              │   │              │
  │              │   │              ├── 1:n ── plans ──1:n── plan_steps
  │              │   │              ├── 1:n ── tool_calls ──1:1(pending)── approvals
  │              │   │              ├── 1:n ── approvals
  │              │   │              └── 1:n ── context_snapshots (is_current 标识当前版本)
  │              │   └── 1:n ── model_usage
  │              ├── 1:1 ── conversations ──1:n── messages (run_id 可空)
  │              └── 弱引用 ── skill_candidates.evidence_task_ids (JSONB)
  └── 1:n ── skills ──1:n── skill_versions ──1:n── skill_evaluations
                     └── 1:n ── skill_candidates

memory_items (source_task_id → agent_tasks，弱关联；向量在 Chroma)
eval_runs ──1:n── eval_cases ──→ agent_tasks
settings (key/value JSONB，独立)
```

### 3.3 字段说明

约定：所有表含 `id`（前缀+ULID 字符串 PK）、`created_at`、`updated_at`（timestamptz, UTC）。下列仅列业务字段。

**users**：`email`(unique) · `display_name` · `is_active`(bool, 默认 true) · `role`(varchar, 默认 owner)

**agent_tasks**：`user_id` FK · `title` varchar(120) · `description` text · `repo` varchar 可空 · `status` enum(`queued/planning/executing/reviewing/waiting_approval/completed/failed/cancelled`) · `model` enum(`glm-5.3/glm-5.3-flash/auto`) · `skill_ids` JSONB(字符串数组) · `latest_run_id` 可空 · 聚合列：`duration_ms` int · `tokens_in` int · `tokens_out` int · `tool_calls` int · `test_pass_rate` numeric(5,4) 可空。索引：`(status, updated_at desc)`、`(user_id)`。

**conversations**：`task_id` FK **UNIQUE** · `user_id` FK · `title` varchar

**messages**：`conversation_id` FK · `run_id` FK 可空 · `role` enum(`planner/executor/reviewer/replanner/user/system`) · `content` text · `tokens` int 可空。索引：`(conversation_id, created_at)`。

**agent_runs**：`task_id` FK · `status` enum(同上) · `model` varchar · `started_at`/`finished_at` 可空 · `replan_count` int 默认 0 · 聚合列同 task（`duration_ms/tokens_in/tokens_out/tool_calls/test_pass_rate`）。索引：`(task_id, created_at desc)`、`(status)`。

**plans**：`run_id` FK · `revision` int（同 run 内递增）
**plan_steps**：`plan_id` FK · `idx` int · `title` varchar · `detail` text 可空 · `agent` enum(AgentRole) · `status` enum(`pending/running/done/failed/skipped/replanned`) · `attempt` int 默认 1 · `tool_call_ids` JSONB

**tool_calls**：`run_id` FK · `plan_step_id` FK 可空 · `server` varchar · `tool` varchar · `args` JSONB · `result_summary` text 可空 · `result` JSONB 可空（原始结果，P2 启用） · `status` enum(`running/succeeded/failed/cancelled`) · `risk` enum(`safe/gated/dangerous`) · `duration_ms` int 可空。索引：`(run_id, created_at)`。

**approvals**：`run_id` FK · `tool_call_id` FK · `tool` varchar · `summary` text · `risk` enum · `status` enum(`pending/approved/rejected/expired`) · `resolved_by` enum(`user/auto`) 可空 · `resolved_at` 可空 · `comment` text 可空。

**agent_execution_logs**：`run_id` FK · `seq` bigint · `event_type` varchar（如 `tool.call.completed`） · `payload` JSONB（完整事件信封 payload）。**UNIQUE(`run_id`,`seq`)** —— SSE `?after=seq` / `Last-Event-ID` 续传的数据源。

**skills**：`name` · `slug` UNIQUE · `description` text · `category` enum(`testing/refactor/debugging/docs/workflow/other`) · `status` enum(`active/draft/deprecated`) · `current_version` varchar · 指标列：`usage_count` int · `success_rate` numeric(5,4) · `evolutions` int · `avg_token_delta` int。

**skill_versions**：`skill_id` FK · `version` varchar · `changelog` text · `content` text · `source_type` enum(`task/evolution/manual`) · `source_ref_id` 可空 · `eval_score` numeric 可空。UNIQUE(`skill_id`,`version`)。

**skill_evaluations**：`skill_id` FK · `version_id` FK 可空 · `suite` varchar · `before_score` numeric · `after_score` numeric · `sample_size` int。

**skill_candidates**：`skill_id` FK 可空（空=新增 Skill） · `kind` enum(`create/revise`) · `proposed_version` varchar · `summary` text · `proposed_content` text · `evidence_task_ids` JSONB · `evaluation` JSONB 可空 `{suite,before,after,sampleSize}` · `status` enum(`pending/approved/rejected`) · `reviewed_by` 可空 · `reviewed_at` 可空。

**context_snapshots**（v0.2 修订：Run 1:N 版本化，不原地覆盖）：`run_id` FK · `version` int（run 内递增，初始快照为 1） · `is_current` bool（当前有效快照；**部分唯一索引** `UNIQUE(run_id) WHERE is_current`，同 run 至多一个当前版本） · `window_tokens` int · `used_tokens` int · `segments` JSONB `[{key,tokens}]` · `trigger` enum(`initial/threshold/manual/routing`)（本快照产生原因） · `before_tokens` int 可空（压缩前 Token 数，initial 快照为空） · `after_tokens` int 可空（压缩后 = used_tokens） · `summary` text 可空（本次压缩生成的摘要内容） · `compressed_at` timestamptz 可空（压缩时间）。索引：`(run_id, version desc)`、`(run_id) WHERE is_current`。

**memory_items**：`layer` enum(`core/episodic/semantic/procedural`) · `content` text · `source_task_id` 可空 · `score` numeric · `usage_count` int · `last_used_at` 可空。向量本身存 Chroma（collection 按 layer），PG 存可查元数据；两者以 `memory_items.id` 关联。

**model_usage**：`run_id` FK 可空 · `task_id` FK 可空 · `model` varchar · `prompt_tokens` int · `completion_tokens` int · `cost` numeric(12,6) 可空 · `latency_ms` int 可空。索引：`(model, created_at)`。

**eval_runs**：`suite` varchar · `task_count` int · `success_rate` numeric · `avg_tokens` int · `status` enum(`running/completed/failed`) · `finished_at` 可空。
**eval_cases**：`eval_run_id` FK · `task_id` · `title` varchar · `passed` bool · `tokens` int。

**settings**（实现定稿 v0.3：与代码一致）：`id` ULID 主键（全库统一主键约定） · `key` varchar UNIQUE（`models`/`routing`/`mcp`/`permissions`/`system`） · `value` JSONB · `note` text 可空。每域一行，PUT 全量覆盖，与前端 Settings 接口一一对应。

## 4. 接口规划（分阶段实现标记）

全部挂 `/api/v1`，完整路径清单以 **docs/06 §3 为准**（前端 `endpoints.ts` 与其一一对应，此处不重复）。分阶段视图：

| 阶段 | 实装接口 |
| --- | --- |
| **P1（本次）** | `GET /api/v1/health`（api/postgres/redis/chroma 各自 `status + latencyMs`，`mcp: []` 占位；**始终 200**，依赖故障体现在各子项——前端徽标按子项判断）、`GET /healthz`（进程存活，恒 200）、`GET /readyz`（就绪探针：**关键依赖（PG/Redis）不可用 → 503**，K8s/本地编排友好）、`/docs` + `/openapi.json` |
| **P2（数据联调）** | dashboard 5 个只读接口 · tasks/runs/skills/settings 的 CRUD 与查询（数据来自 seed 脚本）· approvals 只读 |
| **P3（Agent 闭环）** | `POST /tasks`（触发 Run）· `GET /runs/:id/events`（SSE）· `POST /approvals/:id`（恢复执行流）· `POST /memory/search`（Chroma）· `POST /skills/candidates/:id/review` 等 |

**横切约定**：统一异常处理器（`BizException(code,message,status)` + `RequestValidationError` → 422 错误体 + 兜底 500）；CORS 白名单 `ALLOWED_ORIGINS`（默认 `http://localhost:5173`）；请求日志含 request_id。

## 7. 决策记录（评审后定稿 v0.2）

| # | 决策 | 结论 |
| --- | --- | --- |
| 1 | 响应契约 | ✅ 成功=裸实体 JSON；失败=`{"error":{"code","message","details?"}}`；**不增加全局响应包装** |
| 2 | 补充实体 | ✅ 保留 agent_runs / plans / plan_steps / tool_calls / approvals / skill_candidates / memory_items / eval_runs / eval_cases / settings |
| 3 | Conversation 与 AgentTask | ✅ MVP 采用 1:1，实体职责分离并预留 1:N 扩展：`Conversation`=对话线程（消息挂线程下）；`AgentTask`=开发任务（状态与统计的聚合根）；`AgentRun`=任务的一次执行。**扩展点**：`conversations.task_id` 建普通索引而非 UNIQUE，1:1 由 service 层保证——未来「一任务多会话」只改应用层，不迁移表 |
| 4 | Settings KV+JSONB | ✅ 采用；**敏感信息绝不入库**：GLM API Key 只走环境变量 `GLM_API_KEY`（`SensitiveStr` repr 遮蔽）；`settings` 表 `models` 域仅存 keyMasked/baseUrl/温度等非敏感值 |
| 5 | Phase 1 依赖 | ✅ 不安装 langgraph/chromadb，P3 引入 |
| 6 | ContextSnapshot | ❌ 原地覆盖 → ✅ **Run 1:N 版本化**：每次压缩生成新快照、保留历史；`is_current` 标识当前版本（部分唯一索引 `UNIQUE(run_id) WHERE is_current`）；记录 `trigger/before_tokens/after_tokens/summary/compressed_at`（字段见 §3.3） |

## 8. 额外检查清单（开发前置确认）

| # | 检查项 | 结论 |
| --- | --- | --- |
| 1 | **ULID 生成与唯一约束** | `python-ulid`：`ulid.new().str`（26 位 Crockford Base32，单调趋势、字典序≈时间序，对 B-tree 索引友好）。主键形如 `task_01J…`，前缀由模型 Mixin 按表注入；应用侧生成 + 主键唯一约束兜底，插入冲突重试一次 |
| 2 | **agent_execution_logs 唯一约束** | 数据库级 `UNIQUE(run_id, seq)`；seq 分配器（`max(seq)+1` 事务内分配 / Redis INCR）P3 实装，P1 先落约束与索引 |
| 3 | **SSE Last-Event-ID 续传** | 支持：帧 `id: seq`；重连带 `Last-Event-ID` 头或 `?after=seq` → `WHERE run_id=? AND seq>? ORDER BY seq`，命中 `(run_id, seq)` 索引 |
