## ⚠️ 隔离级别诚实声明（按修订要求）

当前实现的隔离是**应用层访问控制**：路径规范化 + 符号链接/路径逃逸检查 + 授权工作区白名单 + 命令白名单（纵深防御）+ argv 数组启动（无 shell，无注入面）+ 超时终止（含 Windows 进程树 taskkill /F /T）+ 输出字节上限 + 权限矩阵。**它不是操作系统级沙箱**。容器隔离的执行接口（`core/sandbox.SandboxProvider`）已定义并作为唯一执行入口，本地子进程实现（`LocalProcessProvider`）已落地；**容器实现尚未完成**——在落地前，系统提示与 UI 不得宣称「沙箱隔离已完成」。

## 三、关键设计点

1. **幂等**：同一 run 内同工具同参数（JSON 规范化哈希）1 小时内重放返回原 tool_call（status=replayed），异参不命中——对应修订要求「工具重复调用与幂等性」。
2. **审批闸门与 B3 的接缝**：`resume_tool_call`/`reject_tool_call` 已实现并被测试证明（批准后续跑真实写盘；拒绝后 tool_call=cancelled）；B3 把审批 API 的决策动作接到这两个入口即可恢复执行流原位置。
3. **事件溯源**：每次工具执行全链路写 `agent_execution_logs`（seq 每 run 自增；单进程 MVP 安全，多进程并发限制已在 docstring 如实注明）。
4. **工作区**：`WORKSPACE_BASE/<task_id>/`，按任务隔离；`run_tests` 的 paths 参数同样过 Guard，pytest 子进程 cwd 固定为任务工作区。
